# 推量发开放接口文档

面向接入方（SaaS 产品）的一键多平台内容分发服务。本文档可被 AI 直接读取并据此生成实现代码。

- **Base URL**：`https://tlf-365.chuhaibang.com/api/sdk/v1`
- **鉴权**：所有接口需带 `Authorization: Bearer <app_key>`。`app_id` / `app_key` 由推量发后台「子租户管理」创建时一次性下发，请妥善保存。
- **数据格式**：请求体 JSON（`Content-Type: application/json`）；时间戳除特别说明外均为 Unix 毫秒。
- **能力**：账号授权（扫码绑定）、一键发布到 19 个国内平台（另支持 X / LinkedIn / Facebook / Instagram / Reddit / YouTube 等海外平台，见 §3.5）、账号指标采集。
- **接入方式：以 Webhook 为主（见 §8）。** 绑定与发布都是**异步耗时**操作（云端扫码登录、视频上传/转码/审核常需数十秒到数分钟），结果通过 Webhook 事件实时推送。请先在后台配置 `webhook_url`，**用 Webhook 接收结果，不要高频轮询**（耗时不可控、轮询浪费算力）。若你的环境确实无法接收 Webhook，请**联系推量发平台获取《轮询接口补充文档》**（按需提供的额外文档）。

## 1. 响应与错误码

成功响应**大多数接口直接返回数据对象**（见各接口示例）；少数操作型接口返回统一信封 `{code, message, data}`（`code=0` 表示成功）。

错误一律返回统一信封并带相应 HTTP 状态：

```json
{ "code": 40300, "message": "该账号未绑定到当前租户", "data": null }
```

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 40000 | 400 | 请求参数错误 |
| 40100 | 401 | 鉴权失败（app_key 缺失/无效/租户停用） |
| 40300 | 403 | 无权限（如账号未绑定当前租户） |
| 40400 | 404 | 资源不存在 |
| 40900 | 409 | 资源冲突 |
| 50000 | 500 | 服务内部错误 |
| 50200 | 502 | 上游平台异常（含具体平台报错信息，见 `message`） |

> **上游平台报错会被透传给你**，不会吞成笼统 500：
> - 平台**同步校验不通过**（请求/内容不合规，如缺视频、字段格式错）→ `40000`（HTTP 400），`message` 为平台返回的具体校验原因（例：`Invalid input: expected object, received undefined → at publishData.video` = 没传视频）。
> - 平台**处理失败**（如取素材失败、平台内部错）→ `50200`（HTTP 502），`message` 为平台原因（例：`获取视频大小失败: HTTP 405`）。
> - 这两类错误的 `data.upstream_code` 保留平台原始错误码，便于你定位。

## 2. 接入流程总览（以 Webhook 为主）

```
① 配置 Webhook：后台填 webhook_url（一次性，见 §8）
② 绑定账号：POST /auth/start → 展示二维码给用户扫码 → 等待 Webhook authResult
            （status=SUCCESS 绑定成功 / FAILED 失败）
③ 取账号：  GET /accounts 拿 account_id（发布目标，见 §4.1）
④ 发布内容：POST /publish → 拿到 task_id → 等待 Webhook publishResult（逐账号结果）/ publishProcess（进度）
```

> **本平台以 Webhook 推送结果为主。** 绑定要等用户扫码确认、发布要等上游上传/转码/审核，**耗时长且不可控**——请通过 Webhook 接收授权与发布结果（§8），**不要高频轮询**（既慢又浪费算力）。
> 确实无法接收 Webhook 的环境（如本地开发、内网不可达），请**联系推量发平台获取《轮询接口补充文档》**，其中提供按需轮询的查询接口与节流规范。

## 3. 账号授权

### 3.1 获取代理区域 — `GET /proxy/regions`

> **可选增强。** 若你希望让终端用户**自由选择内容分发所用的代理区域**（如「广东-深圳」），在扫码绑定前调本接口取可选区域；不接入此能力则跳过本节，授权时不传 `region`，网关自动按负载均衡分配代理。

Query 参数（可选）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| external_user_id | string | 否 | 你系统内的终端用户 ID。传入则返回该用户**上次选择的区域**，便于默认回显 |

**请求**
```bash
curl "https://tlf-365.chuhaibang.com/api/sdk/v1/proxy/regions?external_user_id=u_10086" \
  -H "Authorization: Bearer <app_key>"
```

**响应**（信封）
```json
{ "code": 0, "message": "ok", "data": {
  "regions": ["广东-深圳", "江苏-南京", "浙江-杭州"],
  "last_selected_region": "广东-深圳"
} }
```

- `regions`：当前**可用且已配置区域**的代理去重区域列表。仅含「启用 + 未过期 + 连通性正常」的代理；**未配置区域的代理不在此列出**（它们仍用于不指定区域时的默认分配）。**已按排序权重从高到低排列**（区域取其下代理的最高权重，平台侧可直接按返回顺序展示给用户）。
- `last_selected_region`：该 `external_user_id` **上次选择的区域**（从该用户**当前名下账号**最近一次选定的区域推断）。以下情况均为 `null`：① 未传 `external_user_id`；② 该用户从未选过区域；③ **该用户名下账号已全部解绑 / 删除**——区域记录随账号存在，账号清空后该值即丢失。无论哪种 `null`，按下方「接入建议」让用户从 `regions` 重新选择即可。

**接入建议（绑定前确认）**：扫码绑定前调本接口，按 `last_selected_region` 做默认选择，并校验它**是否仍在 `regions` 中**：
- 在 → 可直接沿用（也可让用户改选）。
- 不在（该区域当前已无可用代理）或为 `null`（新用户）→ **弹窗让用户从 `regions` 重新选择**。

把用户最终选定的区域作为 §3.2 `POST /auth/start` 的 `region` 传回。

### 3.2 发起扫码授权 — `POST /auth/start`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| platform_code | string | 是 | 目标平台代码，见 §5 |
| password | string | 否 | 云端授权密码，部分平台需要（如抖音）；不需要时省略 |
| external_user_id | string | 否 | 你系统内发起用户的 ID。除事件溯源外，**还用于代理 IP/区域粘性**：同一 `external_user_id` 的多个账号会尽量分配到**同一代理 IP / 地域**。**强烈建议同一终端用户始终传同一个值**；不传则按负载均衡，该用户的账号可能落到不同地域 |
| region | string | 否 | 代理区域（来自 §3.1，如「广东-深圳」）：该账号将**使用此区域的代理**分发。**不传**则默认沿用该 `external_user_id` **上次选择的区域**；若也无历史，则按全局负载均衡分配。详见 §3.4 分配规则 |

**请求**
```bash
curl -X POST https://tlf-365.chuhaibang.com/api/sdk/v1/auth/start \
  -H "Authorization: Bearer <app_key>" -H "Content-Type: application/json" \
  -d '{"platform_code":"XiaoHongShu","external_user_id":"u_10086","region":"广东-深圳"}'
```

**响应**（直接返回对象）
```json
{
  "operation_id": "op_xxx",
  "qr_code": "data:image/png;base64,iVBORw0KGgo...",
  "scheme": null,
  "session_id": null,
  "region": "广东-深圳"
}
```
把 `qr_code`（base64 图片）展示给用户扫码。`region` 为本次**实际生效**的区域（传入值 / 继承的上次值 / `null`），便于回显。`operation_id` 用于在 Webhook `authResult` 事件里对应本次授权（见 §3.3 / §8）。

### 3.3 授权结果（通过 Webhook 推送）

扫码授权是异步的：用户扫码并在 App 内确认后，推量发通过 Webhook 推送 **`authResult`** 事件（见 §8），按 `operation_id`（事件里的 `operationId`）和你传入的 `external_user_id` 对应到本次授权：

- `status=SUCCESS`：绑定成功。事件 `data.data` 含账号信息（`account_id` / `platform_user_name` / `platform_user_id` / `platform_avatar`，部分平台另带 `platformHomeUrl` 用户主页 URL）。
- `status=FAILED`：失败（扫码超时、平台风控、密码错误等），见 `errorMessage`。
- `status=SCAN`：已扫码、等待用户确认（中间态，可忽略）。

绑定成功后，用 `GET /accounts`（§4.1）即可查到该账号并取 `account_id` 用于发布。

> 无法接收 Webhook 时，可改用轮询版授权状态查询接口——见《轮询接口补充文档》（联系推量发平台获取）。

### 3.4 代理区域分配规则（接入必读）

围绕 `region` 的完整行为，便于你设计绑定交互：

1. **区域绑定到账号、长期生效**：授权时生效的 `region` 会**记到该账号**上。此后该账号的所有内容分发都使用**该区域**的代理。
2. **下次扫码默认沿用上次**：同一 `external_user_id` 再次扫码绑定**其它**账号时，若**不传 `region`**，网关默认采用该用户名下账号**最近一次**选定的区域 —— 即「选一次，后续同一用户的新账号都跟随」。要换区域，显式传新的 `region` 覆盖即可。
3. **区域内多代理 + 容量突破**：每个代理对**每个平台**有容量上限（默认 50 账号）。一个区域（如「广东-深圳」）下可能配置了多个代理：
   - 优先分配到该区域内**未达上限**的代理（多代理间负载均衡）；
   - 该区域内代理**全部达上限**时，**仍突破上限**继续分配到该区域内负载最小的代理 —— **保证账号留在所选区域**，不会因为满了就被分到别的区域。
4. **IP 粘性（带单平台上限）**：同一 `external_user_id` 在同一区域内的多个账号会尽量复用**同一个代理 IP**（同用户同 IP，便于风控与地域一致）；但**同一 IP 上同一平台的账号数达到上限（默认 15）后**，该平台的新账号会**滚动分配到同区域的另一个 IP**，避免「同 IP 同平台账号扎堆」被平台风控。不同平台各自计数、互不影响（如同一 IP 上抖音 15 个 + 小红书 15 个）；同区域没有其它可用 IP 时仍留在原 IP（宁可扎堆也不跨区）。
5. **故障转移优先同区域**：账号所用代理过期 / 连通性异常时，网关自动为其换代理，**优先在同一区域内**选其它可用代理；仅当该区域内**无任何可用代理**时，才回退到其它区域（降级，保证可用）。
6. **未指定区域 = 全局分配**：既不传 `region`、该用户又无历史区域时，按全局负载均衡分配（与未接入区域能力时的行为一致）。
7. **区域可能失效**：某区域的代理可能全部过期 / 下线，导致它从 §3.1 `regions` 中消失。因此**绑定前调 §3.1 校验 `last_selected_region` 是否仍可用**，不可用就让用户重选（见 §3.1 接入建议）。

### 3.5 海外平台授权（OAuth 跳转，与国内不同）

国内平台是扫码授权；**海外平台（X / LinkedIn / Facebook / Instagram / Reddit 等）走 OAuth 跳转**，差异如下：

- **无二维码、无代理、无区域**：`POST /auth/start` 对海外平台**不返回 `qr_code`**，而是返回 **`redirect_url`**（OAuth 授权链接）。`region` 字段对海外平台无意义（海外不走代理）。
  ```json
  { "operation_id": "ca_xxx", "qr_code": null, "redirect_url": "https://...composio.../oauth...", "region": null }
  ```
- **引导用户授权**：把 `redirect_url` 让用户打开（新标签或跳转）完成 OAuth；授权完成后浏览器回跳，**结果仍通过 Webhook `authResult` 推送**（与国内一致，见 §3.3 / §8），你照常用 `GET /accounts` 取 `account_id`。
- **`external_user_id` 必填**：海外平台按它隔离用户账号，务必传且同一终端用户保持一致。
- **发布同一接口**：发布走 §6 同一个 `POST /publish`（`platform_code` 用海外平台代码），无需区分上游。海外平台**不支持**国内的可见性 / 分类 / 定时等扩展字段（`extra_fields` 为空）。各平台发布要点（⚠️ 字段仍在联调，以实际返回为准）：

  | 平台 | `platform_code` | 支持类型 | 标题 / 正文字数 | 图片 / 视频（`media_urls` / `video_url`） | 其他约束 |
  |------|-----------------|----------|----------------|------------------------------------------|----------|
  | LinkedIn | `LinkedIn` | dynamic | 正文(commentary) ≤ 3000 | 图片 0–20 张（可选） | 正文必填 |
  | Facebook | `Facebook` | dynamic、**video** | 正文(message) ≤ 5000；视频描述 ≤ 5000 | 图片 0–50 张 / 或 1 个视频 | 正文必填；须有 FB **公共主页（Page）**，发到 Page 而非个人主页；**多图按相册发布，文案可能不随图显示** |
  | Reddit | `Reddit` | **article**（仅文字） | 标题 ≤ 300；正文(Markdown) ≤ 40000 | **不支持图片 / 视频**（仅文字 self 帖） | 标题必填；**必须经 `extra.subreddit` 指定版块**（见下）；正文为 **Markdown**（链接正常，内联图退化为链接）；**不支持图文(dynamic)** |
  | Instagram | `Instagram` | dynamic、**video** | 文案(caption) ≤ 2200 | 图片 1–10 张（1=单图，2–10=轮播）/ 或 1 个视频 | 图文必须含图；**视频走 Reels**（建议 9:16 竖屏、5–90 秒） |
  | YouTube | `YouTube` | video | 标题 ≤ 100；描述 ≤ 5000 | 视频 1 个（必填） | 标题必填、须视频 |
  | X / Twitter | `Twitter` | dynamic、**video** | 正文 ≤ 280（**加权**：中日韩字符算 2、链接固定算 23；X Premium 更高） | 图片 0–4 张 / 或 1 个视频（≤ 512MB、≤ 140 秒） | 图文需正文或至少 1 张图；**图片与视频不可混发**；平台可能按后台策略**禁止含链接发帖**（含 URL / 裸域名时提交同步返回 `40000`，见 message） |

  - 图片 / 视频传**公网可访问的 URL**（推量发后端会自动下载并转交目标平台），无需预先在目标平台上传。
  - **「支持类型」**：`dynamic`=图文动态、`article`=长文（Reddit 的 article 走 Markdown 正文）、`video`=视频。其余类型对该平台不放行（提交会判失败）。
  - 海外平台**不支持**国内的 `visible_type` / `statement` / `category` / `pre_pub_time`（定时）等扩展字段。
  - **Reddit 正文用 `body`（Markdown），不要用 `html_content`**；其 `article` 与 `dynamic` 都发 self 帖（仅内容长短不同）。

  Reddit 的版块通过请求体 `extra` 对象传入（`extra` 是一个透传给上游的自由字典）：
  ```json
  { "platform_code": "Reddit", "tlf_account_ids": ["acc_xxx"], "content": { "title": "标题", "content": "正文" }, "extra": { "subreddit": "test" } }
  ```

> ⚠️ 海外平台授权需用户具备访问该平台的网络环境（VPN/代理由接入方/用户自备，推量发不提供）。

## 4. 账号管理

> **关于 `account_id`（务必先读）**
> - `account_id`（形如 `acc_xxxxxxxx`）是本平台为每个**物理社媒号**分配的**稳定、不透明**标识，**永不变化**。它是你发布、查询、解绑时唯一应使用的账号 id。
> - **当作不透明字符串持久化**（建议列长度 ≥ 40），不要解析其格式、不要假设它等于任何上游/第三方账号 id。同一社媒号无论被谁、重新扫码授权多少次，`account_id` 始终不变；底层登录会话由平台自动维护与去重，你无需关心。
> - 响应里的 `id` 是内部行 ID，**不要**用作发布目标。

### 4.1 列出已绑账号 — `GET /accounts`

Query 参数（可选）：`platform_code`、`status`（active/expired/revoked）。

**响应**（数组）
```json
[
  {
    "id": "row-uuid",
    "account_id": "acc_xxx",
    "platform_code": "XiaoHongShu",
    "platform_user_id": "63ba...",
    "platform_user_name": "示例昵称",
    "platform_avatar": "https://...",
    "platform_home_url": "https://www.douyin.com/user/MS4wLjABAAAA...",
    "home_url_is_profile": true,
    "proxy_region": "广东-深圳",
    "status": "active",
    "custom_label": null,
    "last_authed_at": "2026-06-01T01:00:00",
    "last_sync_at": "2026-06-01T01:00:00"
  }
]
```
> 发布时使用 `account_id`。`id` 为内部行 ID，不要用作发布目标。
> `platform_home_url` = 该账号的**主页 URL**，可直接展示跳转链接、**无需接入方自己兜底**：能拼出用户个人主页就是用户主页，拼不出则退到该平台的 **web 站点首页**。配套字段 `home_url_is_profile` 标明是哪种：`true` = 用户个人主页（按钮可写「前往主页」）/ `false` = 平台站点首页（按钮写「前往平台」）。二者都拿不到的极少数平台才为 `null`（对空值容错即可）。
> 说明：多数平台用 `platform_user_id` 直接拼用户主页；抖音需 `sec_uid`（授权时取作者信息拼）；**快手** web 个人页需 `eid`（灵径接口拿不到），故快手退站点首页（`home_url_is_profile=false`）。
> `proxy_region` = 该账号内容分发所用的**代理区域**（授权时选定，见 §3.1 / §3.4）。未指定区域的账号为 `null`。

### 4.2 查询单个账号 — `GET /accounts/{account_id}`

只读返回该账号当前状态（不触发上游往返）。账号须已绑定到当前租户，否则 403。响应同 §4.1 单条对象。

### 4.3 强制同步单个账号 — `POST /accounts/{account_id}/sync`

从上游拉取最新昵称/头像，并**主动检测该账号在对应平台的登录态**，更新后返回（同 §4.1 单条，**额外多一个 `login_check` 字段**）。
登录态检测结果映射到 `status`：**有效 → `active`；已失效 → `expired`；检测异常（如上游服务被平台风控临时限制）→ 保持原状不误判**。用于需要立即对齐最新状态、或主动核验账号是否仍登录时（例如引导用户重新扫码后，调本接口把 `expired` 复核回 `active`）。

响应比 §4.1 单条多一个字段 `login_check` = **本次登录检测结论**（仅本接口返回，其它接口无此字段 / 为 `null`）：

| `login_check` | 含义 |
|---|---|
| `active` | 检测到登录有效（`status` 已置 `active`） |
| `expired` | 检测到登录失效（`status` 已置 `expired`） |
| `error` | **检测异常**（上游被平台风控临时限制 / 网络或上游错误）——`status` **未更新**，接入方应提示「暂时无法核验，请稍后重试」而非当作失效 |

> 海外（Composio）账号不做此项检测，`login_check` 为 `null`。请把 `login_check=error` 与 `status=expired` 区分对待：前者是「没查成」，后者才是「确认失效」。

### 4.3b 批量同步账号 — `POST /accounts/sync-batch`

一次同步多个账号（等价于对每个 `account_id` 调一次 §4.3）。**灵径无批量接口，网关内部逐账号并发同步**——每个账号都要向上游逐个检测登录态（较慢），故**有条数上限**（默认 **20**，超过返回 `40000`），请分批调用、避免请求超时。

**请求体**
```json
{ "account_ids": ["acc_xxx", "acc_yyy", "acc_zzz"] }
```

**响应**（统一信封，`data` 为数组，与传入顺序一致、自动去重）
```json
{
  "code": 0, "message": "ok",
  "data": [
    { "account_id": "acc_xxx", "platform_code": "XiaoHongShu", "status": "active", "login_check": "active", "platform_home_url": "https://...", "home_url_is_profile": true, "...": "同 §4.3 单条" },
    { "account_id": "acc_yyy", "status": "error", "error": "该账号未绑定到当前租户" }
  ]
}
```

- 成功项 = §4.3 的单账号对象（含 `login_check`）。
- **单个账号失败不影响其它**：该账号项返回 `{account_id, status:"error", error}`（账号不存在/未绑定/上游异常等），其余照常返回。
- 与 §4.3 一样，`login_check=error` 表示「本次没查成、`status` 未更新」，不要当作失效。

### 4.4 解绑账号 — `DELETE /accounts/{account_id}`

仅解除该账号与当前租户的绑定。若该账号已无任何租户绑定，则在上游一并注销。

**响应**（信封）
```json
{ "code": 0, "message": "ok", "data": { "unbound": true, "remaining_bindings": 0 } }
```

### 4.5 获取内容分类 — `GET /accounts/{account_id}/categories?publish_kind=video`

部分平台发布必须带「内容分类」（如哔哩哔哩视频 category 必填，见 §7.1 的 `category` 列）。分类项是**上游动态返回、按账号 + 发布类型**取的，不能硬编码——发布前先用目标账号调本接口取分类树，让用户选，再把所选节点放进 `category` / `sub_category` 提交。

Query：`publish_kind`（`video` / `article` / `dynamic`，必填）。账号须已绑定当前租户。

**响应**（数组，树形）
```json
[
  {
    "yixiaoerId": "cat_001",
    "yixiaoerName": "生活",
    "raw": "...",
    "child": [
      { "yixiaoerId": "cat_001_01", "yixiaoerName": "日常", "raw": "..." }
    ]
  }
]
```
用法：让用户选一级（若该节点有 `child` 再选二级），提交时 `category` = 所选一级节点对象（可去掉 `child`）、`sub_category` = 所选二级节点对象。分类变动极少，可缓存复用（同平台不同账号通常一致）。

> **空分类是正常的**：某账号该发布类型**没有可选分类**时（常见于 category 非必填的平台，如微博视频），本接口返回 **`200` + `data: []`（空数组）**，直接发布即可（不要把空数组当错误）。是否必须选分类看 §7.1 `category` 列是否带 `ᴿ`。
> **唯一会报错的情形 = 账号登录态失效**：此时返回错误信封（`data.upstream_code` 为上游码，如 `172403`）且该账号被置为 `expired` —— 见 §4.6，需引导用户重新扫码授权（对 B站视频等 category 必填平台，登录失效会同时导致取不到分类、发不了，必须先重新授权）。

### 4.6 账号状态与登录态失效（expired）

账号 `status` 三态：

- `active`：正常可用。
- `expired`：**登录态失效**（账号在对应平台的登录已过期）。**不能发布、不能取分类**，需引导用户**重新扫码授权**后才能继续用。
- `revoked`：已撤销 / 已解绑。

**何时会变 `expired`**：

- 平台侧检测到该账号登录过期 → 通过 `accountStatus` Webhook 主动推送（§8）。
- 你调用**取分类（§4.5）/ 发布（§6）**等需要账号登录态的同步接口时，若该账号登录已失效，接口返回错误信封（`data.upstream_code` 携带上游原始错误码），**同时该账号会被自动置为 `expired`**（可随后用 `GET /accounts` 复核其 `status`）。
- 你**主动调用同步（§4.3 `POST /accounts/{id}/sync`）**：会实时检测登录有效性，失效则置 `expired`；反之若检测到仍有效，也会把此前（如因临时失败）误置为 `expired` 的账号恢复 `active`。可用作「主动核验/刷新登录态」的入口。
- **长期不活跃自动回收**：为控制上游按天计费成本，平台会把**超过 14 天（默认值，可能调整）未使用**的国内账号在上游侧解绑并置为 `expired`。「使用」指发布（§6）、取分类（§4.5）、风控操作（§4.7）或重新扫码授权——**轮询检查登录态（§4.3/§4.3b）与触发指标采集（§7）不算使用**（两者常由定时任务自动执行，不代表账号仍在真实使用），因此仅做状态轮询/每日刷指标不能阻止回收。回收时会向你的 webhook 推送一条 `accountStatus`（§8，`data.status="expired"`、`data.reason="inactive_auto_revoked"`）。回收后恢复方式与普通登录失效相同：重新扫码授权即可，`account_id` 不变。

**如何恢复**：引导用户对**同一 `platform_code`** 重新走 `POST /auth/start`（§3.2）扫码授权。重新授权成功后，该物理社媒号的 **`account_id` 保持不变**、`status` 回到 `active`，原有租户绑定与历史数据不受影响。建议你在「账号管理」界面对 `expired` 账号显著标识并提供「重新授权」入口（本平台不提供静默续期接口，恢复登录态须用户重新扫码）。

> ⚠️ **各平台登录有效期差异很大**，`expired` 频率因平台而异。**微信视频号（`ShiPinHao`）登录有效期特别短——通常只有约 1 天**，即用户约每天都需重新扫码授权一次。请在你的产品里对视频号账号做相应预期与提示（如显著的「登录即将过期/请重新授权」引导），避免用户误以为发布功能异常。其余平台有效期普遍长得多（数周到数月不等）。

### 4.7 抖音发布风控解除（目前仅抖音）

抖音对部分账号会触发「发布风控」：发布会失败，`result_summary[].errorMessage` 类似
「检测到您的账号存在风险，请先前往创作者中心登录后单独发布一个作品，发布时会跳出验证…」。
此时可用下面 3 个接口在你自己的界面里**直接完成验证、解除风控**，无需让用户跳到平台官方后台。

**流程**：① 查状态 → 处于风控时按 `check_methods` 让用户二选一 → ②（短信方式）发验证码 → ③ 提交解除。

#### ① 查询发布风控状态 — `GET /accounts/{account_id}/risk-status`

账号须已绑定当前租户、`status=active`。返回：
```json
{ "code": 0, "message": "ok", "data": {
    "risk_status": true,
    "check_methods": [ { "type": "password", "name": "登录密码" }, { "type": "smscode", "name": "短信验证码" } ]
} }
```
- `risk_status=false` → 无风控，可正常发布，无需解除。
- `risk_status=true` → `check_methods` 列出可用的验证方式（`password`=登录密码 / `smscode`=短信验证码）。

#### ② 发送风控验证短信 — `POST /accounts/{account_id}/risk-sms`

仅 `smscode` 方式需要。短信发到账号绑定手机，返回掩码号：
```json
{ "code": 0, "message": "ok", "data": { "mobile": "138****0000" } }
```

#### ③ 解除风控校验 — `POST /accounts/{account_id}/risk-confirm`

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| method | string | 是 | `password`（登录密码）/ `smscode`（短信验证码） |
| password | string | method=password 必填 | 该社媒号的登录密码（本平台仅透传给上游验证，**不落库**） |
| code | string | method=smscode 必填 | ② 收到的短信验证码 |

```bash
# 登录密码方式
curl -X POST .../accounts/acc_xxx/risk-confirm -H "Authorization: Bearer <app_key>" \
  -H "Content-Type: application/json" -d '{"method":"password","password":"<登录密码>"}'
# 短信验证码方式
curl -X POST .../accounts/acc_xxx/risk-confirm -H "Authorization: Bearer <app_key>" \
  -H "Content-Type: application/json" -d '{"method":"smscode","code":"123456"}'
```
`code=0` 表示解除请求已受理，稍后即可重新发布；若仍被拦截可再次查询并解除。

> 安全提示：`password` 是用户社媒登录密码，请仅在用户主动操作时**当场采集、单次使用、不要持久化**；本平台侧也不落库。
> 解除依赖账号登录态有效（`active`）；若 `expired` 请先重新扫码授权（§4.6）。

## 6. 发布

### 6.1 提交发布 — `POST /publish`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| platform_code | string | 是 | 目标平台，见 §5 |
| account_ids | string[] | 是 | 目标账号 ID 数组（来自 §4，须同平台且 status=active） |
| publish_kind | string | 是 | `video` / `article` / `dynamic`（图文），须为该平台支持的类型 |
| title | string | 视情况 | 标题，见 §7 逐平台限制 |
| body | string | 视情况 | 正文/视频简介/图文文案（视频与图文用） |
| html_content | string | 视情况 | 文章正文 HTML（`article` 用） |
| video_url | string | video 必填 | 视频文件 URL |
| cover_urls | string[] | 视情况 | 封面图 URL 数组 |
| media_urls | string[] | dynamic 视情况 | 图文图片 URL 数组 |
| external_content_id | string | 否 | 你侧内容 ID，回查/对账用 |
| sub_task_ids | string[] | 否 | 与 account_ids 等长的子任务 ID；缺省由网关生成 |
| visible_type | int | 否 | 可见范围，见 §7 枚举 |
| statement | int | 否 | 内容声明（如 AI 生成），见 §7 枚举 |
| create_type | int | 否 | 原创/转载声明，见 §7 枚举 |
| pre_pub_time | int | 否 | 定时发布时间（Unix 毫秒），见 §7 各平台窗口 |
| topics | string[] | 否 | **话题**（仅 DouYin文章/知乎文章/易车号文章 是独立字段；其余平台话题写进 body，见 §7.6 坑①） |
| tags | string[] | 否 | 标签（B 站/CSDN/腾讯视频等；与 topics 不同，见 §7.1） |
| location | object | 否 | 位置信息（支持的平台） |
| category | object | 否 | **一级分类**（部分平台必填，如哔哩哔哩视频）；值为分类节点对象，先调 §4.5 取，见 §7.5 |
| sub_category | object | 否 | 二级分类（所选一级分类含子类时） |
| extra | object | 否 | 平台特定扩展字段，透传给上游。目前用于海外 **Reddit 的 `subreddit`**（发 Reddit 必填，见 §3.5） |

> **扩展字段按平台过滤（重要）**：`visible_type / statement / create_type / pre_pub_time / topics / tags / category / sub_category` 会**按目标平台自动过滤**——该平台不支持的字段**静默忽略、不报错**（支持矩阵见 §7.1）。所以「我传了某字段却没生效」基本都是该平台不支持，请查 §7.1。
> 而 `title / body / 文件` 的长度/数量/必填/枚举**由目标平台校验**，不满足会在发布结果（`result_summary[].errorMessage`）里返回失败，请按 §7.2 规范填写。
> 常见坑（visible_type 不传变私密、话题 vs 标签、分类必填）务必读 §7.6。

**请求示例（图文发小红书）**
```bash
curl -X POST https://tlf-365.chuhaibang.com/api/sdk/v1/publish \
  -H "Authorization: Bearer <app_key>" -H "Content-Type: application/json" \
  -d '{
    "platform_code": "XiaoHongShu",
    "account_ids": ["acc_xxx"],
    "publish_kind": "dynamic",
    "title": "周末好去处",
    "body": "分享一个超治愈的地方 #旅行#",
    "media_urls": ["https://cdn/.../1.jpg","https://cdn/.../2.jpg"],
    "cover_urls": ["https://cdn/.../1.jpg"],
    "visible_type": 0,
    "topics": ["旅行"]
  }'
```

**响应**（任务对象）
```json
{
  "id": "task_xxx",
  "external_content_id": "your-content-id",
  "platform_code": "XiaoHongShu",
  "target_account_ids": ["acc_xxx"],
  "account_snapshot": [{ "subTaskId": "...", "platformUserName": "..." }],
  "status": "publishing",
  "total_count": 1,
  "success_count": 0,
  "failed_count": 0,
  "result_summary": null,
  "pre_pub_time": null,
  "created_at": "2026-06-01T02:00:00",
  "updated_at": "2026-06-01T02:00:00"
}
```

> **同步错误（提交即失败，不进入 Webhook 阶段）**：平台在受理前会先校验/取素材，若此时失败，`POST /publish` **同步返回错误信封**而非任务对象——请先判断 HTTP 状态：
> ```json
> { "code": 40000, "message": "Invalid input: expected object, received undefined\n  → at publishData.video", "data": { "upstream_code": 40000 } }
> ```
> - `40000`(400)：请求/内容不合规（上例=`publish_kind=video` 却没传 `video_url`）。按 `message` 修正后重试。
> - `50200`(502)：平台处理失败（如 `获取视频大小失败: HTTP 405`——多为**素材 URL 公网不可达 / 不支持 HEAD 请求**，请确保 `video_url`/`cover_urls` 是公网可访问的直链）。
> - **账号登录态失效**：若提交时账号登录已过期，同样同步返回错误信封，且本次涉及账号会被置为 `expired`（见 §4.6）——请引导用户重新扫码授权后再发布。
> 只有同步校验通过、返回 `status=publishing` 的任务，才会继续通过 Webhook 推送逐账号结果（§6.2）。

### 6.2 发布结果（通过 Webhook 推送）

`POST /publish` 同步返回任务对象（`status=publishing`）后，**发布进度与最终结果通过 Webhook 推送**（见 §8），按 `callBackData` 对应回你的内容：

- **`publishProcess`**：上传/处理进度（`stage` / `stageStatus` / `uploadedParts` / `totalParts`），可选展示给用户。
- **`publishResult`**：单账号最终结果。`taskId` = 你发布时传的 `sub_task_ids[i]`（缺省时取响应 `account_snapshot[].subTaskId`）；`stageStatus=success/fail`；成功带 `publishId`，失败带 `errorMessage`（如「标题超长」等内容不合规原因）。
- `callBackData.external_content_id` = 你发布时传入的内容 ID，用于对账。

每个账号对应一条 `publishResult`；按账号成功/失败数即可判定整单「全部成功 / 部分成功 / 全部失败」。

> 无法接收 Webhook 时，可改用轮询版任务查询接口（`GET /tasks/{task_id}` 等）——见《轮询接口补充文档》（联系推量发平台获取），其中含轮询节流与超时兜底规范。

### 7.5 内容分类（category / sub_category）

`category`（一级）/`sub_category`（二级）的取值是**上游动态分类项对象**，不能硬编码 ID。流程：

1. 发布前用目标账号调 `GET /accounts/{account_id}/categories?publish_kind=<kind>`（§4.5）取分类树。
2. 让用户选一级分类；若所选节点有 `child`，再选二级。
3. 提交时把**所选节点对象**（`{yixiaoerId, yixiaoerName, raw}`，可去 `child`）放进 `category` / `sub_category`。

§7.1 中 `category` 列带 `ᴿ` 的平台**必填分类**（如哔哩哔哩视频、企鹅号/搜狐号/网易号/一点号/爱奇艺/蜂网视频、百家号/AcFun 文章等），不带则上游拒绝。

### 7.6 常见坑（接入必读）

- **坑①「话题」≠「标签」**：多数平台的话题是写在 `body` 正文里的（直接在文案里写 `#话题#`），**没有独立 topics 字段**。只有 **DouYin文章 / 知乎文章 / 易车号文章** 用独立 `topics` 字段；其中**知乎的「标签」其实是话题**，要用 `topics` 传。`tags` 是另一类（B站/CSDN/腾讯视频/企鹅号文章等）。传错字段名会被静默丢弃。按 §7.1 的 `topics` / `tags` 列选字段。
- **坑② visible_type 不传会变私密 / 报错**：很多平台「可见范围」默认值不是公开。想公开必须显式传 `visible_type=0`，且**仅对 §7.1 中 visible_type 列有 ✓ 的平台生效**（其余平台传了也被丢弃，由平台用自身默认）。**凡 §7.1 中 visible_type 有 ✓ 的平台，上游基本都把它列为必填（`ᴿ`），不传会被上游拒绝**——含 **抖音(视频/文章/图文)、小红书(视频/图文)、快手(视频/图文)**、微博视频/图文、头条视频、雪球号、微视、得物、搜狐视频、小红书商家号、豆瓣、CSDN。
- **坑③ 分类必填**：§7.1 `category` 列带 `ᴿ` 的平台不选分类无法发布；分类要先调 §4.5 取（见 §7.5）。
- **坑④ create_type（原创/转载声明）按平台 enum 不同**：取值见 §7.3，别跨平台套用同一个数字。微信视频号视频、爱奇艺视频、快传号文章、豆瓣文章等为必填。
- **坑⑤ 扩展字段静默过滤**：网关只透传 §7.1 中该平台该类型 ✓ 的扩展字段，其余直接丢弃且**不报错**。排查「字段没生效」先查 §7.1，不要怀疑是 bug。

## 8. Webhook（主推送通道，必读）

**授权结果、发布进度/结果都通过 Webhook 推送**——请在后台「子租户管理」为租户配置 `webhook_url`（HTTPS、公网可达）。这是本平台获取异步结果的**主要方式**。

**推送**：推量发向你的 `webhook_url` 发 `POST`，body 为 JSON，带签名头：
```
X-Webhook-Timestamp: <Unix 秒>
X-Webhook-Signature: sha256=<hex(HMAC-SHA256(webhook_secret, "{timestamp}.{rawBody}"))>
Content-Type: application/json
```

**验签**：用后台下发的 `webhook_secret` 对字符串 `"{X-Webhook-Timestamp}.{原始请求体}"` 做 HMAC-SHA256，与 `X-Webhook-Signature`（去 `sha256=` 前缀）比对；并校验时间戳在 300 秒窗口内防重放。验签通过请尽快返回 2xx（耗时处理转异步），非 2xx 会触发重试。

**Body 结构**：事件对象在 `body.data`，用 `body.data.event` 区分类型；`callBackData` 回带你发起时传入的字段（`external_user_id` / `external_content_id` 等），据此对应回你的业务记录。

| event | 含义 | 关键字段（在 `body.data` 内） |
|---|---|---|
| authResult | 授权结果 | `status`(SUCCESS/FAILED/SCAN)、`operationId`、`callBackData`；SUCCESS 时 `data`=账号信息（部分平台带 `platformHomeUrl` 用户主页 URL） |
| publishResult | 单账号发布结果 | `taskId`、`stageStatus`(success/fail)、`publishId`、`errorMessage`、`callBackData` |
| publishProcess | 发布进度 | `taskId`、`stage`、`stageStatus`、`uploadedParts`/`totalParts` |
| auditStatus | 审核状态 | `taskId`、`stage`、`stageStatus`、`openUrl` |
| accountStatus | 账号状态变化 | `accountId`（或 `id`，值为稳定 `acc_xxx`）、`status`；若为「不活跃自动回收」（§4.6）触发，额外带 `reason="inactive_auto_revoked"` 与 `inactiveDays` |
| accountOverview | 账号概览指标 | `accountId`、`followers`/`worksCount`/`totalLikes`/`totalViews` |

**authResult（绑定成功）示例**：
```json
{ "type": "web", "timestamp": "1780385790", "data": {
    "event": "authResult", "status": "SUCCESS", "operationId": "op_xxx",
    "callBackData": { "app_id": "app_xxx", "platform_code": "DouYin", "external_user_id": "u_10086" },
    "data": { "id": "acc_xxx", "platformCode": "DouYin", "platformUserId": "...", "platformUserName": "昵称", "platformAvatar": "https://...", "platformHomeUrl": "https://www.douyin.com/user/MS4wLjABAAAA..." }
} }
```
（`status=FAILED` 时无 `data`，看 `errorMessage`；`SCAN` 为中间态可忽略。）

**publishResult（单账号结果）示例**：
```json
{ "type": "web", "timestamp": "1780374162", "data": {
    "event": "publishResult", "publishType": "video", "taskId": "<你传的 sub_task_id>",
    "callBackData": { "app_id": "app_xxx", "external_content_id": "your-content-id" },
    "stageStatus": "success", "publishId": "5305336098390091", "errorMessage": "", "stages": "push"
} }
```

> **超时兜底**：上游若长时间无回调，推量发也会在生效起点（立即发布=提交时间；定时发布=`pre_pub_time`）约 1 小时后判定该任务终态并推送 `publishResult`——所以你**总会收到最终结果**，无需轮询催。

## 9. 指标采集

- `POST /metrics/accounts/{account_id}/refresh`：触发一次账号概览采集（异步），返回 `{code:0,...,data:{triggered:true}}`。采集结果通过 Webhook `accountOverview` 事件推送（见 §8），也会写入下方历史。
- `GET /metrics/accounts/{account_id}?days=30`：返回按日快照数组 `[{snapshot_date, followers, works_count, total_likes, total_views}]`（按需查询历史，非实时）。
