# 推量发 · 轮询接口补充文档（按需）

> **本文档为补充件**，仅供**确实无法接收 Webhook** 的环境（本地开发、内网不可达等）使用。
> 推量发的**主推送通道是 Webhook**（见《推量发开放接口文档》§8）——绑定要等用户扫码、发布要等上游上传/转码/审核，**耗时长且不可控**。轮询既慢又消耗算力，**能用 Webhook 就别轮询**。
> 使用本文档接口前，请先联系推量发平台确认开通。

- **Base URL / 鉴权 / 错误码**：同主文档（`Authorization: Bearer <app_key>`）。
- **平台代码、发布参数规格、字段矩阵**：见主文档 §5 / §7。

---

## 0. 轮询纪律（务必遵守）

- **节奏**：授权阶段 **2~3 秒/次**，发布阶段 **3~5 秒/次**，禁止更高频。
- **停止条件（到终态/错误立即停，切勿无限轮询）**：
  - 授权：`status ∈ {success, failed, timeout}` 即停。
  - 发布：任务 `status ∈ {success, partial, failed, cancelled}` 即停。
  - 收到 HTTP 4xx/5xx：按错误码处理，**不要对同一请求反复重试**。
- **超时兜底**：上游长时间无回调时，服务端会自动判定终态（授权返回 `timeout`、发布任务落 `failed`/`partial`），所以轮询**总会终止**，据此结束即可。

---

## 1. 查询授权进度 — `GET /auth/status/{operation_id}`

`operation_id` 来自 `POST /auth/start` 的响应。

**响应**
```json
{
  "status": "pending",
  "platform_user_name": null,
  "platform_user_id": null,
  "account_id": null,
  "error_message": null
}
```

| status | 含义 | 是否停止轮询 |
|---|---|---|
| pending | 等待扫码/确认中 | 否，继续轮询 |
| success | 绑定成功，`account_id` / `platform_user_name` 已返回 | 是 |
| failed | 失败，见 `error_message` | 是 |
| timeout | 超时未完成（默认约 10 分钟内无结果）→ 停止轮询，让用户重新发起授权 | 是 |

> 发起授权后约 10 分钟仍无结果即返回 `timeout`；未知/过期的 `operation_id` 同样返回 `timeout`。
> `success` 后如需再次确认账号，请用 `GET /accounts`（主文档 §4.1，长期有效）。

---

## 2. 查询单个账号状态 — `GET /accounts/{account_id}`

只读返回该账号当前状态（不触发上游往返）。账号须已绑定到当前租户，否则 403。响应为主文档 §4.1 的单条对象。用于按需查某账号 `status`（active/expired/revoked）。

> 需强制对齐上游最新状态时，用 `POST /accounts/{account_id}/sync`（主文档 §4.3，按需调用，勿轮询）。

---

## 3. 查询任务进度 — `GET /tasks/{task_id}`

`task_id` 来自 `POST /publish` 的响应。轮询直到 `status ∈ {success, partial, failed, cancelled}`。

```json
{
  "id": "task_xxx",
  "platform_code": "XiaoHongShu",
  "status": "partial",
  "total_count": 2,
  "success_count": 1,
  "failed_count": 1,
  "result_summary": [
    { "subTaskId": "st1", "status": "success", "publishId": "p_123", "errorMessage": null },
    { "subTaskId": "st2", "status": "failed",  "publishId": null,    "errorMessage": "标题超长" }
  ],
  "created_at": "...", "updated_at": "..."
}
```

| status | 含义 | 是否停止轮询 |
|---|---|---|
| pending / publishing | 进行中 | 否，继续轮询 |
| success | 全部成功 | 是 |
| partial | 部分成功 | 是 |
| failed | 全部失败 | 是 |
| cancelled | 已取消 | 是 |

`result_summary[].status`：`success` / `failed` / `""`（进行中）；`progress` 为上传进度、`audit` 为审核信息（部分平台/阶段才有）。

> **超时兜底**：自生效起点（立即发布=提交时间；定时发布=`pre_pub_time`）起约 1 小时仍未到终态时，服务端会把未回报子任务标记 `failed`（`errorMessage` 含「超时未收到平台回调」）、任务落 `failed`/`partial`。任务终会到达终态，轮询到终态即停。

---

## 4. 任务列表 — `GET /tasks`

Query：`page`(默认 1)、`page_size`(默认 20，≤100)、`status`、`platform_code`。返回分页 `{ items, total, page, page_size }`。用于历史任务查询（非实时，勿用于高频轮询进度）。
